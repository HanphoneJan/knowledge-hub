# 文档处理与切分

> 面向：要加解析器 / 加切分策略、或者排查“入库了但搜不到 / 搜出来是空的”的人。

---

## 1. 链路的七个阶段

```
blob（内容寻址，无扩展名）
  → ① 解析        按 documents.file_name 的扩展名查派发表
  → ② 切分策略    六选一，KB 级配置，默认 recursive；失败一律退回默认并记 note
  → ③ 解析校验    空内容 / 乱码率 / 长度异常
  → ④ 切分体检    块大小分布
  → ⑤ PII 检出    统计**掩码前**的命中（否则报告永远是 0）
     └ 按库开关决定是否掩码（只掩索引侧）
  → ⑥ 嵌入 + 索引 文本腿（512 维 dense + BM25 稀疏）与视觉腿（扫描页 / 照片，逐页入队）
  → ⑦ 终态结算    任务全部终态 且 索引里实际有多少点 ⇒ 才置 ready
```

两个容易踩的顺序约束：

- **策略在解析之后、掩码之前。** 切分策略作用于“内容”（语义分组、父块、上下文生成），而 PII 掩码必须作用在**最终要入库的文本**上。
- **PII 先检出再掩码。** 计数必须记掩码前的，否则开了掩码的库报告永远显示“0 处 PII”，用户会以为库是干净的。

### 1.1 一个贯穿全链路的约束：扩展名在数据库行里

内容寻址存储**刻意不保留原文件名**：同一份文件可能被多个文档版本引用，按内容 sha256 存放才能天然去重，而这就意味着 blob 路径没有扩展名。

```python
# ❌ 每个 blob 都是“无扩展名”，解析器一律 UnsupportedFormat
suffix = blob_path(doc.blob_sha).suffix

# ✅ 扩展名 / mime 的真相在 DB 行里
parse_to_chunks(path, file_name=doc.file_name, ...)
```

这条一旦写错，**解析器与页图渲染端点会各炸一次**（同一个根因、两处症状），所以解析入口强制要求传 `file_name`。

## 2. 解析器派发表

`PARSERS` 是一张 `后缀 → 处理器` 的表，**加一种格式 = 加一条**：

| 后缀 | 处理器 | 备注 |
|---|---|---|
| `.pdf` | pymupdf 逐页解析 | 唯一原生带坐标的格式；逐页判定扫描页 |
| `.docx` | python-docx + 标题层级修复 | 需要时转 PDF 拿坐标 |
| `.xlsx` | 按工作表解析 | 表头/数值**按列下标**对齐，块文本带 `[工作表: <name>]` 前缀 |
| `.pptx` | 按幻灯片解析 | — |
| `.md` `.markdown` `.txt` `.json` | 纯文本 | 按 Markdown 结构切 |
| `.html` `.htm` | 去标签，按 `h1~h6` 切 | — |
| `.csv` | 首行当表头 → Markdown 表 | — |
| `.jpg` `.jpeg` `.png` `.webp` `.bmp` `.tiff` | **无文本层**，标记为扫描件 | 只走视觉腿 |

上传白名单是从这张表派生的，不是另写一份清单：

```python
SUPPORTED_SUFFIXES, IMAGE_SUFFIXES = _derive_suffix_sets(PARSERS)
```

这么做的原因是可测：测试可以断言“这两个常量确实等于 `_derive_suffix_sets(PARSERS)` 的结果”，于是“有人又手写了一份白名单”会被抓住。历史上真实的漂移形态就是“白名单里有、实现没有”。

派发记录统一返回 `(chunks, scan_pages, is_scanned)`。文档类解析器只产出块列表，由适配器补成统一形状。

## 3. 六种切分策略

切分方式做成**知识库级单选**（`knowledge_bases.chunk_strategy`），默认 `recursive`。下表同时给出各自的边界与代价——选哪种取决于文档形态，没有通吃的一种。

| 策略 | 边界在哪 | 代价 / 前提 | 动坐标？ |
|---|---|---|---|
| `fixed` | 定长 + overlap 硬切 | 会把句子切断，语义上最差；存在的意义是**评测基线** | PDF 不执行 |
| `recursive`（**默认**） | 标题 > 段落 > 硬切 | 默认值，同时也是**向后兼容的契约**：不传策略与显式传 `recursive` 的输出必须**逐字相同** | 否 |
| `semantic` | 句子向量相似度低于阈值就断开 | 需要**句向量编码器**；阈值 0.55，过小的段落会合并 | PDF 不执行 |
| `parent_child` | 子 = 递归块，父 = 章节（文本）/整页（PDF） | 父块文本**不进向量库**；父块在 PG 里冗余存一份，检索命中后证据正文用父文本、角标仍指子块 | 否 |
| `late` | 同 `recursive`，但整篇过 Transformer 按 span 池化 | 受编码模型 **512 token 上限**约束：超长文档会被截断 | 否 |
| `contextual` | 同 `recursive`，每块前置 LLM 生成的上下文 | **需要显式配外部 LLM**；未配置时降级为 `recursive` 并记一条“未配置 LLM，不生效” | 否 |

**PDF 为什么不执行 `fixed` / `semantic`：** 这两种策略会**重排文字**，而坐标依赖“块的文本与它在页面上的位置一一对应”。重排后坐标全部失效 ⇒ 对 PDF 直接保持结构切分，并记一条说明。这不是“忘了支持”，是取舍。`parent_child` 在 PDF 上的父子划分是**按页**（不是按章节）。

### 3.1 失败一律降级

与检索腿“挂了只 `skipped`”是同一条纪律：未知策略名、策略抛异常、依赖缺失（没有编码器 / 没有 LLM）三种情况都退回 `recursive`，**结论写进 `documents.quality.strategy_notes`**，让用户看得见“我选的策略没生效”。

### 3.2 注册表与正交性

`STRATEGIES` 是一张 `策略名 → 实现标签` 的表（真正分派在 `apply_strategy`）。API 白名单与知识库字段校验都从它派生，所以不会再出现“白名单里有、实现没有”的漂移；测试断言注册表与对外 schema 里的枚举**相等**。

策略是**单选 profile**，父块 × Late 理论上可以叠加但组合爆炸，本期不做。**改策略后必须重新摄取才生效**——它只影响新入库的块。`GET /kb/{id}` 的 `stale_strategy_docs` 就是“还停在旧策略的当前文档数”，用于提示重摄取欠账。

## 4. 分层校验

三层，**保守原则**贯穿：只在能确凿判断时报告，识别不出就放行。

| 层 | 检查什么 | 失败处置 |
|---|---|---|
| **格式** | 扩展名白名单 + **文件头嗅探**（PDF `%PDF`、ZIP `PK`、PNG/JPEG/WebP/BMP/TIFF 魔数） | 明显不符 → 上传 **415** |
| **解析** | 空内容 / 乱码率 > **5%** / 长度异常（< 100 字 或 > 1000 万字） | 空内容 → `failed`；乱码/长度 → 记 `status_msg` 与 `quality`，不阻断 |
| **切分** | 块大小分布（块长标准差 > 均值的一半、有 < 50 或 > 5000 的块） | 写进 `documents.quality` 与日志，**不阻断入库** |

为什么格式层要“只在确凿时报错”：识别不出、看着像纯文本的一律放行，否则测试 fixture 和“奇怪但合法”的文件会被全挡掉；嗅探逻辑本身也刻意保守——只有**明确认出是另一种二进制**才算不符。

为什么解析层要新增校验：在这之前，上传时查了白名单与大小，但**解析出空内容 / 乱码 / 切分异常没有任何检查**——一份解析出 0 个块的 Office 文档会被走“当成扫描件”的分支直接置 `ready`，**静默入库一个空文档**。现在的判据把两件事分开了：

```python
if not parsed:
    if not (is_scanned or scan_pages):
        raise IngestError("解析后没有任何可检索内容（不是扫描件，也没有文本层）",
                          code="PARSE_EMPTY")
    # 扫描件/照片：本来就没有文本层，交给视觉腿
```

校验模块是**纯函数**：不碰数据库、不加载模型，所以每条判据都能直接单测——“乱码率 4.9% 与 5.1% 分别怎样”是普通测试用例，不需要起服务。

### 4.1 `documents.quality` 记录什么

```jsonc
{
  "parse":   {"chars": 18432, "garbled_rate": 0.0, "issues": []},
  "chunking": {"total": 74, "avg_size": 249.1, "stddev": 88.3, "min": 62, "max": 511,
               "acceptable": true, "issues": []},
  "strategy_notes": ["策略 semantic 会重排文字、破坏坐标，PDF 保持结构切分"]
}
```

扫描件 / 照片的 `parse` 段是 `{"skipped": "扫描件/照片，无文本内容，走视觉腿"}`——**“没有文本层”要如实写成“跳过”，不要写成“通过”**。

## 5. 坐标与结构化处理

坐标的**存储格式与渲染链路**见 [检索与融合](./retrieval.md) 第 6 节，这里只讲摄取侧怎么产出它们。

### 5.1 扫描页判定：别把“没有文本层”直接当扫描页

```python
if not page.get_text().strip():
    if page.get_images(): scan_pages.append(pno)   # 扫描页 → 走视觉腿
    else:                 blank_pages.append(pno)  # 空白页 → 跳过
```

用“文本长度小于某个阈值”来判定会把**空白页**也算成扫描页；矢量图形不产生文本层但不是扫描件。整份文档“一页文本层都没有”才算扫描件。扫描页有处理上限（默认 **50 页**）：视觉编码约 15 s/页，超了就拒绝并给出原因，而不是让一个任务跑几十分钟——这是个**显式的**上限，不是超时。

### 5.2 多栏阅读顺序

表单类 PDF 的常见问题是双栏排版被按 y 坐标读成“左一行右一行”。做法是轻量 XY-cut：按行的水平区间**找一条没有任何行跨越的竖直切线**，递归地左右分栏，单栏自然退化为原排序。

### 5.3 Office 文档的标题与坐标

**标题层级**：读段落的样式名，`Heading N` → `#`×N。这里必须同时看两个信号：**光看样式名不够，还要看字号**——加大字号的普通段落会被误套成标题级别。

**坐标**：Office 格式**没有原生坐标**（实测原生块 0/8 有坐标）。做法是转成 PDF，在**转换版**上算坐标，平均可定位覆盖约 99%。由此得到一条不变量：

> 坐标与被渲染的页面必须来自同一个文件。所以“画框用哪个文件”由调用方决定，底图渲染函数不许自己去找原件——否则给 Office 文档画框会直接报错。

### 5.4 表格的结构化

表格文本统一**转成 Markdown 表**入库，而坐标（`row` / `col`）保持不变——文本给人读，坐标给前端排网格。坐标只能从**按行**的单元格取：

```python
len(tbl.cells) != row_count * col_count      # ❌ 一维扁平列表，合并单元格会让长度对不上
tbl.rows[ri].cells[ci]                       # ✅ 与 extract() 的行一一对应，None = 合并单元格
```

即：**文本用 `extract()`，坐标用 `rows[i].cells`，按行号对齐**。`XLSX` 还多一条：表头与数值必须**按列下标**对齐（不能各自过滤空值，否则某一列缺失会让整张表错位）。

表格 JSON 化 + 表格描述（同一份 `extract()` 网格的三次投影）：

| 产物 | 落点 | 给谁 |
|---|---|---|
| Markdown 表 | `content_norm`（后半段） | 人读 / 上下文 |
| **表格描述**（“N 行 × M 列；表头：…”） | `content_norm`（**开头一句**） | **检索**（让“一览表”类查询能命中） |
| **结构化网格** | `table_json`（JSONB 列） | 前端渲染真表格 / 程序化读取 |

- 描述是**纯规则、离线生成**（`locations.describe_table`）——默认生成层“零外传”，所以**不发外部 LLM 生成摘要**；需要 LLM 描述的部署要显式配外部 LLM。
- 三份同源于一个网格，**不各自解析**（文本与 JSON 两条路走同一张 `grid`）。
- `table_json` 只对 `kind="table"` 成立；正文 / 扫描页 / chat 为 `null`。

### 5.5 清洗去噪

去重复页眉页脚（同一份文档里出现 ≥3 次、且短于 40 字的行）、连续空行、零宽字符。只在**高置信**时删——清洗误删正文的代价远大于留下一点噪声。

PDF 的页眉/页脚在**解析期**单独清：`locations._repeated_lines` 先扫全文、找出跨页重复的短行，在**分段之前**把它们丢掉——因此坐标（bbox）只覆盖保留下来的正文行，L3 不变量不受影响。⚠️ 只做**精确重复**判定：带页码的页眉（“第 3 页”与“第 4 页”文本不同）**不会**被删——宁可留噪声也不误删正文。

## 6. PII 掩码与归属判定

### 6.1 掩码

检出类型：身份证、手机号、邮箱、银行卡、学号。三条设计约束：

1. **默认关闭**（按库开关）。个人知识库的核心用途之一恰恰是“搜我自己的手机号 / 证件号”，默认掩码等于把这个用途关掉。开关按库，所以同一个工作区里可以“日记库保持原文、要发出去的证件库开掩码”。
2. **只掩码索引侧，不动原件。** blob 原件、预览页图、文件下载全部保持原文。代价说清楚：**开了掩码就搜不到自己的号码**——这是刻意的取舍，不是 bug。
3. **检出报告只读。** 只回答“哪里有、有多少”，**不返回原文片段**——否则报告本身就成了新的泄露面。

掩码会改变文本长度，所以命中邮箱之后块的字符偏移会相对原文偏几个字符。影响很小（高亮用的是**块级 bbox**，不是字符级偏移），但不能为了保持长度而保留完整邮箱——那等于没掩。实现上有两个“不报错但结果是错的”细节必须处理：

- **同跨度的重叠命中要去重**：一串 18 位数字可同时命中身份证与银行卡，跨度完全相同，按起点依次拼接会把同一段文字复制一份；
- **掩码长度要自适应**：固定写法对 6~7 位数字会**比原文更长**，掩了个寂寞还改了内容。

### 6.2 归属判定（owner_classifier）

导入历史语料时，要先判断“这份文档是不是本人的”——他人文档不该进本人的检索与时间线。

**不用硬编码人名清单**（那会漏人）。改成**规则式**：从文件名分段里识别“姓 + 1~3 字名”的候选，配停用词表排除“毕业设计”这类误判。判定优先级（顺序即优先级）：

| 序 | 判据 | 结论 |
|---|---|---|
| 0 | 文件名含本人标识 | 本人（最先短路） |
| 0.5 | **名单型文档**（表格里列了多人） | 他人 |
| 1 | 英文简历特征 + 人名形态文件名 | 他人 |
| 2 | 文件名含显式他人姓名 | 他人 |
| 3 | 注册表给了 `other` | 他人 |
| 4 | 文件名含“姓+名”候选 | 他人（泛化，防名单外的陌生人） |
| 5 | 正文含显式他人姓名 | 他人（**不设次数阈值**） |
| 6 | 正文含本人标识 | 本人 |
| 7 | 否则 | `unknown`（模板 / 技术资料） |

第 5 条不设次数阈值是个刻意的取舍：设阈值会漏判正文里只出现两次的他人自传、以及“表格里列了他人学号与出生日期”的花名册。误伤方向（把本人文档误判为他人 → 少索引几条）可接受；**漏判方向不可接受**。

第 1 条（英文简历）也是实测补的：一份全英文简历含电话与邮箱，但全文没有一个中文字，前几条判据全都匹配不到——特征 = 正文有独占一行的全大写节标题 + 文件名呈人名形态。

### 6.3 聊天切片不能拿归属判定当门禁

聊天记录的每一个切片几乎都判 `other`（因为聊天必然出现对话方的名字）。拿它当门禁会把**整个聊天库导空**。所以导入任务**记录**判定、**不拦截**。

通用形态的教训：**分类器的结果要按用途决定“是门禁还是信号”**——在这里它是“给时间线分组用的信号”，不是“能不能入库”的判据。

## 7. 入库之后：怎么知道自己没漏

| 症状 | 先查什么 |
|---|---|
| 文档 `ready` 但搜不到 | 三个索引集合里这个 `doc_id` 有没有点；文本腿能靠重建任务修，视觉腿要重新摄取 |
| 状态卡在中间态 | 任务是否全部终态。**“没有待办任务却还在中间态”是不可能的状态**，worker 启动时会补扫一次 |
| 某一类内容完全搜不到 | 该腿能力是否可用（`GET /health` 的 `available_legs`），而不是“库里没有这种数据” |
| 页数对不上 | 视觉腿是**一页一个任务**，所以同一文档同时有多条未完成任务是正常状态——去重键必须包含任务负载，否则第二次调用会命中第一次那条 |
| 检索质量悄悄变差（不报错） | BM25 的词表统计量。它在入库时加、删除时减；**任何绕开统一删除入口的路径都会让它虚高** → idf 被压平 → 罕见词不再罕见 |

最后一条值得单独强调：**“入库时加、删除时减”的统计量，必须有一个统一的减法入口。** 它漂移的表现是质量下降、不是报错——所以对账里专门有一条判据：`chunks` 行数应等于语料统计里的文档数。
