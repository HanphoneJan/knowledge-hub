# Knowledge Hub · 设计文档

> **一句话定位**：单机自部署的**多租户知识库 + RAG 检索**服务 —— 把办公文档、聊天导出、照片收进不同知识库，
> 用四种召回方式（向量 / BM25 / 子串 / 视觉）找到原文，并**带坐标级引用**回答问题。

本目录面向**读代码的工程师**：讲的是设计意图与权衡（为什么这么做、代价是什么、什么情况下会降级），
不是功能介绍，也不是使用手册。使用方式见仓库根 [`README.md`](../README.md)，
HTTP 契约见 [`DESIGN-API.md`](./DESIGN-API.md)。

## 从哪读起

- **只想知道架构** → [architecture.md](./architecture.md) 的「进程模型」与「存储分工」两节，10 分钟。
- **关心检索质量 / 算法** → 直接跳 [retrieval.md](./retrieval.md)；它有独立的实测数据表。
- **关心文档处理** → [ingestion.md](./ingestion.md) 的「六种切分策略」与「分层校验」两张表。
- **只想看怎么部署、怎么跑起来** → 回根 [`README.md`](../README.md) 与 `deploy/README.md`。

## 全局速览

```
                    ┌──────────────────────────────┐
   浏览器 / 客户端 ─▶ │ api（FastAPI）:8010           │ ─▶ Qdrant :6333   （派生索引）
                    │  检索编排 · 托管前端           │ ─▶ PostgreSQL :5432（真相源）
                    │  MCP /mcp · A2A /a2a          │
                    └───────┬──────────────────────┘
                            │ 入队 / 查进度
                            ▼
                    ┌──────────────────────────────┐        ┌───────────────────────┐
                    │ worker（无监听端口）           │        │ visual_service :8020  │
                    │  轮询任务 · 摄取 · 清理        │        │  只做"文本/图片→向量"  │
                    └──────────────────────────────┘        └───────────────────────┘
```

| 维度 | 现状 |
|---|---|
| 检索 | **四条腿** RRF 融合：dense（`bge-small-zh-v1.5`，512 维）· BM25（自实现，jieba）· trigram（Postgres）· 视觉（`colSmol-500M` late-interaction 多向量 MaxSim，128 维） |
| 存储 | **Postgres 是真相源**；Qdrant 三个集合（`kb_dense` / `kb_sparse` / `kb_visual`）是可重建的派生索引；原件走内容寻址 blob |
| 租户 | 三档可见性（`private` / `workspace` / `global`），过滤条件**只在 `auth.py` 一处构造**，请求体不接受租户字段 |
| 生成 | 默认**抽取式**（答案句子全部摘自原文，零外传）；接外部 LLM 需显式配置且按库/按用途开关 |
| 规模 | 契约 82 个端点声明 · pytest 1252 项 · 后端 ≈ 23.8k 行（87 模块）· 前端 ≈ 16k 行 |

> 文中所有性能数字都标注了测量口径（哪条腿、多少候选、什么机器）。
> 单个数字脱离口径没有意义 —— 例如「overall R@10」把四类语料混在一起算，就不能用来做取舍。
